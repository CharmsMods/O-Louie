# Recording And Replay Boundary

This folder will own recording session state, the encoded packet store, replay-buffer queries, bookmarks, MP4 muxing, and export jobs.

The intended storage model is encoded packets plus an in-memory index, not raw frames. Clip exports should query keyframe-aligned packet ranges and remux asynchronously without blocking capture or encoding.

Keep session orchestration, packet persistence, muxing, export queueing, bookmarks, and timebase logic separate.

Current implemented pieces:

- `Timebase`: QPC/session-relative nanosecond conversion and sample-count duration conversion.
- `SessionClock`: captures and validates one QPC-derived 100 ns origin compatible with WGC `SystemRelativeTime` and WASAPI packet QPC timestamps.
- `DiskWriteFault`: classifies no-space, access, write-protection, path, destination, and general I/O failures while retaining the failed recording subsystem, operation, path, standard error, and optional FFmpeg backend error.
- `PacketStore`: binary `packets.dat` append storage for encoded packets, in-memory indexing, incremental lightweight per-track statistics, keyframe-aligned range queries, payload reads, and recovery by scanning the complete packet prefix. Keyframe-aligned ranges exclude an earlier H.264 sample whose duration overlaps the selected keyframe while retaining overlapping AAC. Recovery reports file size, recovered bytes, packet count, and truncated-tail bytes. Create, append, visibility flush, and close failures retain the first typed write fault. `SnapshotForExport` flushes writer visibility and copies paths plus the index under one lock so live export planning never observes a partial append.
- `SessionManifest`: writes current version 3 `session.json` metadata for one H.264 track, zero or more direct AAC tracks, and validated bookmark markers/default windows through a same-directory temp plus atomic replacement. Incomplete temps are cleaned; a complete temp and prior destination survive publication failure. It reads complete unpublished manifest temps as well as version 1 video-only and version 2 H.264/AAC manifests for recovery.
- `VideoExportPlan`: combines a ready `SessionManifest` with an immutable active or recovered `PacketStore` export snapshot, validates every packet-bearing current-version H.264/AAC track against manifest metadata, requires keyframe-aligned video starts by default, and returns cross-media stream metadata plus one normalized interleaved `MuxPlan`. Configured AAC tracks with no packets in the selected range are reported through `omitted_audio_track_ids` and left out of the MP4 rather than blocking export or fabricating silence. Legacy version 1 recovery continues to ignore unmanifested historical audio packets.
- `ActiveRecordingClip`: derives the current H.264 end from one flushed live snapshot, clamps a requested duration to available session time, aligns to the previous keyframe, includes overlapping AAC packets, reports empty configured AAC tracks, and builds the existing normalized MP4 mux request.
- `ActiveRecordingBookmark`: creates a marker at the current encoded-video end, resolves the default zero-post-roll bookmark range, and reuses `ActiveRecordingClip` so marker time and export planning come from the same flushed live snapshot.
- `VideoRecorderClipCommandQueue`: owns bounded typed clip/bookmark requests from the Win32 command thread to the recorder worker.
- `ClipExportQueue`: owns bounded low-priority MP4 mux jobs, one background worker, explicit success/failure completions, repeated-command rejection, and drain-on-shutdown behavior.
- `Bookmark`: bookmark marker data, collection add/find/snapshot behavior, and export-window calculation with session-start clamping.
- `MuxPlan`: validates packet ranges and track definitions, keeps packet-bearing tracks, sorts packet refs for mux interleaving, and normalizes output timestamps for a future MP4 writer.
- `Mp4Muxer`: validates MP4 mux requests for exactly one H.264 stream plus zero or more direct raw-AAC streams, matching plan/packet/metadata track ids, required decoder configuration, keyframe starts, and per-track monotonic DTS; reports `BackendUnavailable` when FFmpeg is not configured; classifies stale-temp/open/header/packet/trailer/close/publication write failures; cleans incomplete temps; and preserves complete temps plus old destinations after failed atomic publication.
- `BuildVideoMp4MuxRequest`: adapts a ready cross-media `VideoExportPlan` into the validated H.264/AAC `Mp4Muxer` request shape without writing MP4 payloads.
- `Mp4MuxPayloadReadStats` / `Mp4Muxer::DryRunPayloadRead`: walks a validated MP4 request, reads referenced packet payload bytes from `packets.dat`, verifies per-track timestamps, and reports separate video/audio packet and byte totals without creating output files.
- `Mp4Muxer::BackendAvailability`: reports whether the LGPL dynamic FFmpeg backend was configured by CMake, names the expected dynamic libraries, and keeps writer availability explicit without silently falling back.
- `Mp4MuxStreamSetupStats` / `Mp4Muxer::ValidateStreamSetup`: when FFmpeg is configured, allocates an in-memory MP4 output context, configures H.264 plus all requested AAC streams with their AVCC/`AudioSpecificConfig` data, reports setup facts, then frees the context without writing packets or files. `ValidateVideoStreamSetup` remains as a compatibility forwarding name.
- `Mp4Muxer::WriteMp4`: when FFmpeg is configured, converts stored Annex B H.264 payloads into length-prefixed MP4 samples, passes raw AAC access units through to their configured streams, writes all packets through FFmpeg's interleaved writer, finalizes the trailer, and atomically renames the result.
- `VideoRecorderPipeline`: owns the explicit production H.264/AAC sequence from FFmpeg availability and video/audio preflight through one shared-clock `PacketStore`, unbounded WGC/WASAPI capture, session-owned bookmarks, active clip/bookmark planning and background muxing, ordered export-queue drain and input stop, video/PCM drain, H.264/AAC finalization, cross-media manifest/store recovery/export planning, and atomic full MP4 save. Its recorder/audio-service thread uses best-effort `Capture` MMCSS scheduling; live WASAPI workers use `Audio`; persisted Balanced/Capture First policy is propagated consistently to capture, encode, and hardware-codec configuration without changing process priority. A live PacketStore fault stops capture once, prevents further unsafe store writes, drains/shuts down bounded work, attempts recovery/export, and retains the first typed diagnosis. Background clip export failures remain job-local and report their path; its backend interface keeps stage ordering and cleanup testable without live capture.
- `VideoRecorderSession`: owns asynchronous Start/Stop and Save plus active clip/bookmark commands, idle/starting/recording/stopping/saved/failed snapshots, typed queued/saved/failed export events, and state callbacks. It contains worker failures and keeps recorder and mux work off the Win32 message thread.
- `RecordingRecovery`: performs one bounded, deterministic startup scan on a worker, classifies complete, recoverable-prefix, incomplete-metadata, corrupt, and already-exported sessions, retains the first scan error, recognizes complete unpublished manifest/MP4 temps, protects existing outputs, remuxes durable packet prefixes, and moves discarded sessions to reversible `sessions/discarded` storage. Its snapshot/action boundary drives tray recovery and discard commands without blocking the hidden-window thread.
