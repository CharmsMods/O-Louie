# Encoding Boundary

This folder will own hardware-only video encoding.

MVP direction is Media Foundation hardware H.264 MFT with D3D11-aware input where practical. Direct NVENC, AMD AMF, or Intel VPL backends can be added later behind the encoder backend boundary if Media Foundation control is not enough.

There must be no CPU video encoding fallback. If no compatible hardware encoder is available, recording start should fail with a clear user-visible reason and a detailed log entry.

Current implemented pieces:

- `MfHardwareH264EncoderProbe`: validates generic MVP H.264 requests, including even NV12/H.264 dimensions, nonzero FPS and bitrate, positive GOP seconds, and B-frames disabled. It enumerates Media Foundation hardware H.264 encoder MFTs for NV12 input and H.264 output, records backend names/CLSIDs/enumeration flags, and reports explicit failures when Media Foundation cannot start, enumeration fails, or no hardware encoder is available.
- `MfHardwareH264EncoderSession`: activates the selected hardware H.264 MFT, derives a deterministic media-type plan from the validated request, unlocks asynchronous transforms when required, attaches an `IMFDXGIDeviceManager` when a caller supplies a D3D11 device and the transform is D3D11-aware, applies basic codec settings where the transform accepts them, and in Capture First mode requests low latency plus the fastest quality-versus-speed value. Every codec control reports support, modifiability, application, readback, and the value actually accepted. It configures H.264 output and NV12 input media types, records D3D11/asynchronous traits, owns transform teardown, can submit generated NV12 DXGI input samples or caller-owned NV12 textures, releases retained input samples as corresponding output drains, reports the bounded pending-sample count, can issue a final drain command, inspects Annex B/SPS/PPS/IDR presence in drained packets, captures SPS/PPS payload bytes into a config record, and derives AVCC extradata bytes for future MP4 metadata.
- `H264PacketStore`: maps drained H.264 packet metadata to `PacketStore` video packet metadata, carries SPS/PPS/AVCC config readiness for future session metadata, and appends Annex B payload bytes to caller-owned stores.
- `SyntheticVideoRecordingSession`: owns the recorder-facing synthetic video handoff around a configured H.264 encoder session, caller-owned D3D11 device, and caller-owned `PacketStore`; it submits generated frame timings, drains available packets, captures the first valid H.264 config, appends packets, and reports explicit stage failures.
- `BgraVideoRecordingSession`: owns the encoder-facing BGRA texture handoff around a configured H.264 encoder session, caller-owned D3D11 device/context, reusable `GpuBgraToNv12Converter`, reusable encoder-sized NV12 texture and VideoProcessor view, and caller-owned `PacketStore`; it converts caller-owned BGRA textures, submits the converted NV12 texture, drains available packets, captures H.264 config, appends packets, and final-drains the hardware transform during recorder shutdown.
- `VideoEncodeWorker`: synchronously drains `VideoFrameQueue` frames into a caller-owned `BgraVideoRecordingSession` with an explicit per-call frame budget, `Timebase` timestamp normalization, first session-failure preservation, and processed/dropped/remaining frame reporting. The record-layer worker schedules it for the long-running tray flow.
- `VideoEncodeChain`: owns the synchronous composition of `VideoFrameQueue`, `BgraVideoRecordingSession`, and `VideoEncodeWorker` with explicit queue options, BGRA session options, worker timing options, a default drain budget, and final encoder draining. Capture and background thread lifetime remain outside this layer.
- `VideoEncodeThread`: owns the event-driven, bounded-batch production encode worker and applies thread-scoped MMCSS scheduling without changing process priority.
- `VideoCaptureEncodeBridge`: implements the captured video frame sink boundary by forwarding leased app-owned BGRA frames into `VideoEncodeChain`, optionally starting the chain timebase on the first captured timestamp, propagating exact multi-frame overflow drops, and exposing bounded chain draining. It does not own live capture or a background encode thread yet.
- `VideoLiveCaptureEncode`: composes WGC frame-copy handoff, `VideoCaptureEncodeBridge`, serialized sink/drain access, repeated bounded drain ticks while capture runs, and final draining into a caller-owned `VideoEncodeChain`. It remains manual and duration-bounded.
- `VideoRecordingSetup`: owns recorder-facing video preflight/setup for the current video-only path. It validates source dimensions, H.264 config, queue/drain settings, timing, `PacketStore` track id, and live runner options, then builds the H.264 track definition, `VideoEncodeChainConfig`, and live WGC encode options before preparing a chain against caller-owned runtime dependencies.
- `VideoRecordingRunSession`: owns the video-only duration-bounded recording run boundary around setup preflight, caller-owned encoder/D3D/`PacketStore` prepare, and `VideoLiveCaptureEncode` run orchestration. It keeps preflight, setup, and run failures distinct for later recorder state composition.
- `VideoRecordingBootstrap`: owns the current video-only runtime dependency bootstrap. It resolves the requested or primary monitor, creates the matching D3D11 device/context, initializes the Media Foundation hardware H.264 session, creates the temporary H.264 `PacketStore`, prepares `VideoRecordingRunSession`, and keeps monitor/D3D/encoder/store/preflight/prepare failures distinct.
- `VideoRecordingMetadata`: builds validated video output metadata from explicit inputs or from a prepared bootstrap session, including PacketStore paths, video track id, H.264 SPS/PPS/AVCC config, requested encoder config, encoder/backend traits, monitor details, source dimensions, and output dimensions. It can be adapted into the record-layer `SessionManifest` shape for persistence.
- `O'LouieEncodeSmoke`: exposes the real hardware H.264 probe, transform-configuration, short synthetic NV12 frame-sequence submission, generated BGRA-to-H.264 submission, bootstrap-backed live-runner copied-WGC-frame-to-H.264 submission, available-output draining, packet-inspection, video metadata assembly, session manifest write/read, recovered video export-plan handoff, video MP4 mux request handoff, FFmpeg backend availability reporting, FFmpeg MP4 video stream setup validation when configured, MP4 payload-read dry run, configured-only video MP4 write attempt, video session, and temporary PacketStore append smoke paths manually. The session smoke creates a primary-monitor D3D11 device, reports DXGI device-manager attachment state, and still does not own tray-driven recording or export queueing.
